## 0.6.1 - 2026-11-20

Commit `740db511e1a3`; release record `pub:sha2-256:wtjldijhpqbayogvqxvmqvpbg7v6y4w67byicgy4v2ez267uxojq`.

### Added
- pubdeploy.contract: the provider contract as code. CONTEXT, NEED, RESULT, RESULT_OPTIONAL, TYPE and TYPE_OPTIONAL are the names a provider may rely on, equal to README's "Provider contract" lists; Need, Result and Ran come from it; problems(kind) and hook_problems(hook) say what the walk says of a type or a hook it leaves out (registry.type_problems is now contract.problems). A provider's tests import pubdeploy.contract and pubdeploy.testing, and nothing else of pubdeploy
- pubdeploy.testing: World.providers() gives the sustenaut.needs entry points and sustenaut.walk hooks the walk loads in the world, together as a Providers, in place of the installed packages' (None, the default, keeps them); walk_needs(world, needs, types, fulfil) walks needs in the world's context and gives the deploy-journal/2 document as data

### Internal
- The suite walks with a stand-in provider built from pubdeploy.contract alone, and no longer installs pubsec: the scenarios that tested pubsec's own types are pubsec's

## 0.5.1 - 2026-11-18

Commit `71b6fa9349bb`; release record `pub:sha2-256:kgmqkh4pc2djcl32bdkw6s2beqyifh2mwqtdtl6wb3mqjg5b3hmq`.

### Added
- pubdeploy machine prints a unit's needs as a state machine (a documented subset of XState v5 JSON, which python-statemachine runs too: machine.load); the deploy block's run section (schema 1: default_mode, parallel, a need's mode and after-edges) may only narrow the generated default, and pubrules sync --check checks it; need types say serial and stop (signal, shorten, continue with a stop_warning); walk --need ID walks, and with --fulfil fulfils, only those needs, refusing when one they wait for is not ready; --budget-seconds caps a check or a fulfil

### Fixed
